# 应用宝官网测试用例（业务 / 产品用大白话写，agent 翻译后执行）

> **你只管写中文，不用学任何关键字。**
> 把「要验证什么、预期怎样」用大白话写清楚即可，agent 会自动把每一句话翻译成浏览器操作。
> 步骤写成 `1. 2. 3.` 或者 `-` 列表都行；也可以写成一段连贯的话（如「在搜索框输入微信并回车」）。
>
> 写完后让 agent 跑一次 `translate_cases.py`（或直接在 `cases.md` 里写同样的大白话，
> 执行引擎会在运行时自动翻译），然后 `pytest` 即可。

---

## TC01 首页加载冒烟

场景：验证应用宝官网首页能正常打开，关键元素都看得到
前提：浏览器可正常访问 https://sj.qq.com/
预期：标题显示应用宝；搜索框、品牌logo、内容区块、顶部导航都可见
步骤：
1. 打开应用宝官网
2. 看看页面标题是否正常
3. 搜索框在不在
4. 品牌logo可见吗
5. 内容区块有没有
6. 顶部导航显示了吗

## TC02 搜索功能

场景：搜一个应用名（默认微信），应该能出结果
前提：已在应用宝官网首页
预期：跳到搜索结果页，至少返回 1 个相关结果
步骤：
1. 在搜索框输入微信并回车
2. 等页面跳到 /search
3. 数一下微信相关的有多少个结果
4. 确认结果数量至少有1个

## TC03 分类导航

场景：点一下顶部分类导航，应该能跳转且内容正常
前提：已在应用宝官网首页
预期：点击后页面标题非空，跳转后内容区块正常显示
步骤：
1. 看看导航在不在
2. 点击导航
3. 内容区块有没有

## TC04 应用详情 / 下载

场景：从搜索进到应用详情页，下载按钮要能看到
前提：已在应用宝官网首页
预期：成功进详情页，能看到下载按钮
步骤：
1. 在搜索框输入微信并回车
2. 等结果出现
3. 点开第一个结果进详情
4. 下载按钮能看见吗

## TC05 页脚完整性 & 响应式

场景：页脚栏目要齐全；切到手机大小也不能有横向滚动
前提：已在应用宝官网首页
预期：页脚常见栏目都在；移动端页面有内容且无横向溢出
步骤：
1. 页脚栏目齐全吗
2. 切到手机大小375x667
3. 移动端页面有内容吗
4. 移动端有没有横向滚动

## TC06 搜索王者荣耀并下载

场景：搜一个游戏「王者荣耀」，应该能进到它的详情页并看到下载
前提：已在应用宝官网首页
预期：能搜到王者荣耀，进入详情页且下载按钮可见
步骤：
1. 在搜索框输入王者荣耀并回车
2. 等结果出来
3. 点开第一个结果进详情
4. 下载按钮能看见吗

## TC07 排行榜第一应用下载

场景：验证排行榜第一的应用，点击它的下载/安装入口后能否弹出二维码/扫码下载弹窗。预期应有二维码可下载，但实测 PC web 端该详情页点下载仅唤起应用宝/微软商店客户端、不弹网页二维码，此预期与真实站点不符，记为站点缺陷（保留观察步骤以暴露问题）
前提：已在应用宝官网首页，排行榜页面可正常访问
预期：打开排行榜、点进首位应用、点击下载/安装入口后弹出二维码/扫码下载弹窗（PC 版应用宝为「微软商店安装」入口），报告需包含该二维码截图；实测 PC web 端无网页二维码，记为缺陷
步骤：
1. 打开排行榜
2. 点击排行榜第一的应用
3. 点击下载按钮
4. 观察二维码/扫码下载弹窗出现
