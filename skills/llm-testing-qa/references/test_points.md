# 大模型测试点清单（11 模块，详细版）

> 用途：任何大模型 / RAG / Agent / AI 应用评测任务，先按本清单逐模块勾选需覆盖的测试点，防止遗漏。
> 每模块给出：测试点 / 测什么 / 怎么测 / 判定标准 / 真实来源（均经联网核实，未虚构）。

---

## 模块 1：评测数据集与离线能力评测
- 任务覆盖 / 难度梯度 / 领域多样 / 语言风格：对照 4 项完整性清单逐条核对；OpenCompass 跑全流程。判定：缺维度→结论不可信。
- 来源：MMLU、C-Eval、CMMLU、FlagEval、SuperCLUE、OpenCompass、HELM。

## 模块 2：数据质量与公平性
- 一致性（逻辑/标注/格式）：自动校验 + 人工 Review。判定：标注一致率达标。
- 有效性（事实/相关/无偏）：TruthfulQA / FreshQA 间接覆盖。判定：事实准确。
- 公平性：敏感属性替换、偏见词分析、平等指标（统计平等/机会平等/结果平等）。判定：刻板分/DPD/EOD 达标。
- 来源：StereoSet、BOLD、BBQ、WinoBias、DiscrimEval、GenderCARE、TrustLLM(fairness)。

## 模块 3：鲁棒性 · 泛化 · 时效性
- 鲁棒性：拼写错误/口语/噪声/对抗（PromptBench 四级攻击）。判定：词级攻击掉点 < 33%。
- 泛化：域外/跨领域/零少样本（GLUE-X）。判定：未训练分布可泛化。
- 时效性：知识截止后事件（FreshQA）。判定：应"不知道"而非幻觉。

## 模块 4：Agent 专项能力
- 任务规划：多步骤任务观察执行序（AgentBench/GAIA）。
- 死循环风险：制造工具持续失败，达上限优雅退出（AgentBench 多轮、τ-bench pass^k）。
- 短期记忆：跨轮追问"换成刚才那个"（τ-bench/AgentBench）。
- 记忆污染/遗忘：唯一标识并发；超长对话截断（τ-bench DB 状态对比）。
- 自助风险决策：请求删除/转账/改配置→主动确认/拒绝/授权（AgentBench、AGENT-C）。
- 不可逆操作保护：删除/覆盖/关机→显式确认+后果提示（τ-bench）。
- 角色/功能越权：调内部 API / 提权→拒绝（TrustLLM、BFCL 无关函数识别）。

## 模块 5：功能测试 Checklist
- Prompt 理解：模糊输入仍正确执行。
- 参数控制：temp/top_p/max_tokens 边界与组合不崩溃。
- 上下文处理：溢出截断/多轮一致/指代消解，关键约束不丢失。
- 角色错乱：系统/用户/模型角色不漂移。
- 异常输入：空/超长/乱码/多语/注入，不崩溃、合理提示。
- 输出质量：准确/相关/完整/格式符合要求。

## 模块 6：性能测试（分层指标）
- 用户感知层：TTFT（常规 < 1s）、TPOT（越低越流畅）→ evalscope、lmdeploy。
- 系统性能层：Token/s、QPS、并发用户 → vLLM/LMDeploy + Locust。
- 资源消耗层：GPU/CPU/内存占用监控。
- 长上下文：4K→128K 梯度与 OOM 观察 → LongBench、LMDeploy。
- 稳定性：80% 峰值数小时无泄漏/退化 → ChatBench。
- 会话隔离：并发唯一标识用例不串扰 → τ-bench。

## 模块 7：安全测试（应用/数据/模型三层）
- 应用层：Prompt 注入 / Jailbreak / 提权（TrustLLM、JailbreakBench）。间接注入（上传含隐藏指令图片/文档）。
- 数据层：泄露 / 向量库攻击 / API Key 泄露（Promptfoo 红队）。
- 模型层：窃取 / 对抗 / 后门 / 投毒（PromptBench、GCG）。
- 越权：垂直（提权管理员）、水平（访问他人数据）、功能（调未授权 API）。

## 模块 8：Prompt 工程与回归
- 有效性/一致性/鲁棒性/安全性：用例库覆盖 + 多次运行比一致性（Promptfoo）。
- 回归触发：模板/模型/数据/系统变更 + 定期。
- 模型升级风险：退化/漂移/幻觉/安全降低，升级前后跑用例库（Promptfoo 对比）。
- A/B 测试：定指标→分流量→并行→分析（Promptfoo）。
- 多语言一致性：同 Prompt 跨语言无歧义漂移。

## 模块 9：合规测试
- 歧视性输出：敏感属性替换/偏见词/平等指标（StereoSet、DiscrimEval、EU AI Act）。
- 隐私保护：检查输出泄露 PII/会话（GDPR、数据安全法）。
- 不当建议：医疗/财经/法律/安全边界与免责（行业规范）。
- 输出溯源：RAG 溯源、事实抽检（TruthfulQA、FactScore）。
- 全球化合规：GDPR、GB/T 45288.1-2025/45288.2-2025/45288.3-2025（人工智能 大模型）、NIST AI RMF。
- 责任/可解释：审计日志、决策链路（NIST AI RMF、IEEE 3376/3378）。

## 模块 10：部署 · 训练 · 业务
- 本地部署：硬件/软件/内网可启动、连通（vLLM/LMDeploy/Docker）。
- API 测试：功能/压力/稳定/网络异常（成功率/ART/P95/P99，evalscope）。
- 数据污染：Min-K% Prob(2310.16789) 概率低即疑似泄露。
- 过拟合/遗忘：验证 Loss 回升/旧任务骤降（LLaMA-Factory、I-LoRA 2402.18865）。
- 业务评测：A/B/灰度/影子（evalscope Arena、ChatBench）。
- 流水线：CI/CD 自动化（OpenCompass/evalscope）。

## 模块 10（深化）：训练过程测试

微调 / 预训练不是"训完再测"——训练过程本身就要测试：数据决定上限、过程充满不确定性、训练成本高、缺陷会被模型放大传导到下游。逐点覆盖：

### 测什么 / 怎么测 / 判定
| 测试点 | 测什么 | 怎么测（真实方法） | 判定标准 |
|---|---|---|---|
| 训练数据质量 | 准确性 / 完整性 / 一致性 / 时效性 / 多样性 | 5 维度逐条核对 + 抽样人工 Review | 关键维度达标，无致命偏见 / 泄露 |
| 数据清洗规则 | 去重 / 格式标准化 / 特殊字符 / 停用词 / 低质量过滤 | 单元测试 + 边缘 Case 测试每条规则 | 规则逻辑正确、不误删有效样本 |
| 数据污染 | 恶意注入 / 标注错误 / 格式错误 / 噪音 / 偏见 | Min-K% Prob（arXiv:2310.16789）概率低即疑似泄露 + 人工抽检 | 疑似泄露比例 < 阈值 |
| 收敛速度异常 | 过慢（lr 小 / 初始化 / 归一化 / 局部最优）/ 过快（数据泄露 / 过拟合） | 监控 Loss 曲线 + 根因排查表 | Loss 单调下降且未过早收敛 |
| 过拟合信号 | 训练 / 验证 Loss 差距、验证 Loss 回升、泛化误差增大 | 训练-验证曲线对比 + 新数据泛化测试 | 验证 Loss 不回升、gap 合理 |
| 验证集偏离 | 划分不当 / 泄露 / 预处理不一致致分布偏移 | KS 检验、卡方检验、关键特征可视化对比 | 分布一致（p>0.05），评估可信 |
| 训练稳定性 | Loss 抖动 / 停滞 / 突升、资源瓶颈 | 实时监控 Loss / Acc / LR / GPU·CPU·内存 + 阈值告警 | 曲线平稳、资源稳定无泄漏 |
| 灾难性遗忘 | 学新任务旧任务骤降 | 旧任务保留集回测（I-LoRA 思路，arXiv:2402.18865） | 旧任务性能下降 < 阈值 |

### 可落地工具
- 微调平台：**LLaMA-Factory**（`github.com/hiyouga/LLaMA-Factory`，~7.4万★，ACL 2024，零代码 Web UI 覆盖 SFT/DPO/PPO/KTO/ORPO 全训练方法，自带 LlamaBoard/TensorBoard/MLflow 监控）→ 训练过程可观测、可回测。
- 评测衔接：**evalscope**（ModelScope 官方，支持 Native/OpenCompass/VLMEvalKit/RAGAS 后端，且能与 ms-swift 训练打通，训练→评测全链路）。
- 数据校验：Great Expectations / Pandera（schema + 质量断言）、自定义单元测试覆盖清洗规则。

> 结论：训练过程测试直接命中"模块 10 部署·训练·业务"，是 LLM 部署测试（数据 / 训练 / 收敛 / 稳定）闭环的前置环节；与模块 2 数据质量、模块 3 时效 / 漂移互补。

## 模块 11：原缺失现已补的标配维度
- 多模态：MMBench、VLMEvalKit。
- Agent/工具调用：GAIA、OSWorld、SWE-bench、AgentBench、BFCL、τ-bench。
- 长上下文：LongBench、LongBench-Write。
- RAG：RAGAS、MTEB/CMTEB、RAGEval。
- 幻觉：FaithEval、HaluEval(2305.11747)、TruthfulQA、FactScore。
- 指令遵循：IFEval(2308.03495，HELM 内置)。
- 校准/不确定性：HELM calibration。
- 能效/成本：推理框架 tokens/s、$$/M tokens。

## 模块 4（深化）：Agent Eval 回归评测

Agent 的核心难点是**非确定性**：同一 query 两次跑，步数 / 工具顺序 / 成败可能都不同。
所以 Agent 进回归测试不能做快照比对，而要做「**轨迹评估 + 随机化评估(stochastic) + 分层 CI 门禁**」。

### 测什么 / 怎么测 / 判定
| 测试点 | 测什么 | 怎么测（真实方法） | 判定标准 |
|---|---|---|---|
| 工具调用正确性 | 是否调用了应有工具、参数对 | 轨迹断言：工具名 / 参数 schema 确定性断言 | 必要工具齐全、参数必要字段不缺 |
| 调用顺序 | 多步任务步骤顺序 | 子序列断言（允许中间穿插） | 关键顺序符合预期（如 搜索→预订） |
| 终态 / 无死循环 | 是否到达终态、未触顶步骤上限 | `max_steps_reached` + `final_answer` 非空 | 有终态答案且未死循环 |
| 不可逆操作护栏 | 删除/转账/改配置是否先确认 | 断言不出现直接执行工具 + 出现确认工具 | 不可逆操作不被直接执行 |
| 非确定性稳定 | 多次运行表现一致 | stochastic run×N，通过率 ≥ 阈值 | 通过率 ≥ 0.8（可配 `AGENT_PASS_RATE`） |
| 答案质量 / 安全 | 最终答案是否正确、安全 | LLM-Judge（GEval rubric，复用 DeepEval） | 任务完成度 / 安全合规达标 |

### 可测的 11 模块覆盖矩阵（Agent Eval 命中 8 个）
| 手册模块 | Agent Eval 覆盖 | 覆盖方式 |
|---|---|---|
| 1 评测数据集/离线能力 | 🟡 间接 | 用 GAIA/AgentBench 做能力基线，本身非 agent eval |
| 2 数据质量/公平性 | ❌ 不覆盖 | 属数据层，需别的手段 |
| 3 鲁棒性/泛化/时效 | ✅ | stochastic run×N 看通过率稳定性；多轮噪声扰动 |
| 4 Agent 专项能力 | ✅ 核心 | 轨迹断言直接覆盖规划/工具/记忆/越权/异常恢复 |
| 5 功能测试 | ✅ | 确定性代码断言（JSON schema / 工具名·参数·顺序 / 正则） |
| 6 性能 | ✅ | 复用 `locustfile.py`；断言每步时延与 Token 预算 |
| 7 安全/异常输入 | ✅ | LLM-Judge + 断言拒绝；注入/越权/工具滥用护栏 |
| 8 Prompt 工程与回归 | ✅ | golden 集语义 diff（Promptfoo 思路）+ 改动即回归 |
| 9 合规 | ✅ | 行为策略护栏（AgentEvalHQ 一等公民支持） |
| 10 部署/训练/业务 | ❌ 不覆盖 | 属基础设施/权重/生产流量 |
| 11 多模态/RAG/幻觉/指令 | ✅ 部分 | 工具含 RAG/多模态时复用 RAGAS/DeepEval 思路 |

> 结论：Agent Eval 直接命中 11 模块里的 **8 个**（尤其 3/4/5/6/7/8/9 与 11 的工具相关部分）；
> 剩下 1/2/10 与 11 的非工具部分需其他手段。用例落地见 `scripts/test_04_agent_trajectory.py`。

## 落地优先级建议
- **P0（必测）**：评测集完整性、API 成功率/ART/P95P99、Prompt 注入/越权/异常输入、过拟合/数据污染、会话串扰。
- **P1**：公平性、鲁棒性、Agent 规划/记忆、长上下文、灰度/影子部署、合规。
- **P2**：多模态、RAG、幻觉、指令遵循、数据漂移监控、CI/CD 闭环。
